## 1. สิ่งที่แก้

```diff
 procedure SetMXCSR;
 var
-  w2: word = 8064;
+  w2: dword = 8064;   // ldmxcsr loads 32 bits: a word left 2 stray bytes in MXCSR (crash)
 begin
   asm
            Ldmxcsr w2
   end;
 end;
```

เปลี่ยนชนิดตัวแปร `w2` จาก `word` (2 ไบต์) เป็น `dword` (4 ไบต์) เท่านั้น
ค่าเดิม 8064 (= `$1F80`) ไม่เปลี่ยน

## 2. อาการที่พบ

`NeonMenuFxEditor.exe` (โปรแกรมแต่งเมนูเอฟเฟกต์) ปิดตัวเองทันทีตอนเปิด
ไม่มีหน้าต่างแจ้ง error ใดๆ

รันใน gdb ได้ผลดังนี้:

```
Thread 1 received signal SIGSEGV, Segmentation fault.
SETMXCSR () at sdl3.pas:66
#1  SDL3_$$_init$ () at sdl3.pas:73
#2  fpc_initializeunits ()
#3  $main () at NeonMenuFxEditor.lpr:15
```

โปรแกรมพังตั้งแต่ขั้น initialization ของ unit `SDL3` ก่อนโค้ดของโปรแกรมจะเริ่มทำงาน
ส่วน NeonBeads, NeonTrail และโปรแกรมแต่งอีก 2 ตัวที่ใช้แพ็กเกจเดียวกันกลับเปิดได้ปกติ

## 3. สาเหตุ

ตอนโหลด unit `SDL3` จะเรียก `SetMXCSR` เพื่อตั้งรีจิสเตอร์ MXCSR
(ตัวควบคุม floating point แบบ SSE) เป็นค่ามาตรฐาน `$1F80` (ปิด exception ของ floating point ทุกชนิด)
ปัญหาอยู่สองจุดที่เกิดร่วมกัน:

1. **คำสั่ง `ldmxcsr` อ่านข้อมูล 32 บิต (4 ไบต์) เสมอ** แต่ `w2` ประกาศเป็น `word` ขนาด 2 ไบต์
2. **`var w2: word = 8064` เป็นตัวแปรบน stack** compiler จึงเขียนค่าลง stack แค่ 2 ไบต์
   แล้ว `ldmxcsr` อ่านไป 4 ไบต์ ตามที่เห็นใน disassembly ของโค้ดจริง:

```
word  (ตัวเก่า):  mov %ax,-0x4(%rbp)      ; เขียน 2 ไบต์
                  ldmxcsr -0x4(%rbp)      ; อ่าน 4 ไบต์ -> 2 ไบต์บนเป็นขยะบน stack
dword (ตัวใหม่):  mov %eax,-0x4(%rbp)     ; เขียนครบ 4 ไบต์
                  ldmxcsr -0x4(%rbp)      ; อ่านค่า $00001F80 ที่ถูกต้อง
```

2 ไบต์บนที่อ่านเกินมาคือข้อมูลเก่าที่โค้ดก่อนหน้าทิ้งไว้บน stack
ถ้าไม่ใช่ศูนย์ ค่าที่ใส่ลง MXCSR จะมีบิตสงวน (reserved bits 16-31) ถูกตั้ง
CPU จะปฏิเสธด้วย General Protection fault (#GP) และโปรแกรมพังทันที

**เหตุที่บางโปรแกรมพัง บางโปรแกรมไม่พัง:** ค่าขยะบน stack ขึ้นกับว่าโค้ด initialization
ที่รันก่อน unit `SDL3` ในโปรแกรมนั้นทิ้งอะไรไว้
(unit ที่ใช้, ลำดับการ initialize, เวอร์ชันของโค้ด)
โปรแกรมที่ทำงานได้วันนี้จึงอาจเริ่มพังได้ทุกเมื่อหลังเพิ่ม unit หรือแก้โค้ดแล้ว build ใหม่
รวมถึง NeonBeads และ NeonTrail

## 4. การพิสูจน์

`test\d_word.pas` และ `test\d_dword.pas` ใช้ `SetMXCSR` แบบเดียวกับใน sdl3.pas ทุกตัวอักษร
โดยเรียกหลังจากโค้ดอื่นทิ้งค่าไม่เป็นศูนย์ไว้บน stack:

| `d_dword.pas` (แบบใหม่) | `w2 as dword: OK, MXCSR loaded` |

คอมไพล์ทดสอบเองได้ด้วย:
`C:\lazarus\fpc\3.2.2\bin\x86_64-win64\fpc.exe d_word.pas`

  โค้ดจึงเหลือแหล่งเดียว

## 6. เหตุผลที่เลือกวิธีนี้

- **แก้ที่ต้นเหตุ:** `ldmxcsr` ต้องการตัวถูกดำเนินการ 32 บิตตามสเปกของ CPU
  การใช้ `dword` จึงเป็นการใช้คำสั่งอย่างถูกต้อง ไม่ใช่การหลบปัญหา
- **ไม่เปลี่ยนพฤติกรรม:** ค่าที่ตั้งลง MXCSR ยังเป็น `$1F80` เท่าเดิม
  (เป็นค่าที่ตั้งใจไว้ตั้งแต่แรก) ต่างกันแค่ตอนนี้ได้ค่านี้ทุกครั้งแน่นอน
- **กระทบน้อยที่สุด:** แก้ 1 บรรทัดในไฟล์เดียว ไม่แตะ API ของแพ็กเกจ
  ทุกโปรแกรมที่ใช้ SDL3_package ได้ประโยชน์โดยไม่ต้องแก้โค้ดตัวเอง
